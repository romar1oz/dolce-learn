# Dolce Learn

Корпоративная offline-first LMS для обучения, проверки знаний и аттестации производственного персонала **Dolce Pharm**.
Методист создаёт курсы (видео, PDF, документы, тесты, тренажёры), назначает их сотрудникам; сотрудник скачивает курс
на смартфон, учится без интернета, а прогресс и результаты автоматически синхронизируются с сервером.

| Слой | Технологии |
|---|---|
| Frontend (PWA) | React 19, TypeScript, Vite, Tailwind CSS v4, компоненты в стиле shadcn/ui (Radix), Lucide, React Router, TanStack Query, Zustand, React Hook Form + Zod, Recharts, pdf.js |
| Офлайн | Service Worker (Workbox через vite-plugin-pwa), IndexedDB (Dexie), Cache Storage, собственная очередь синхронизации |
| Backend | Python, FastAPI, SQLAlchemy 2, Alembic, Pydantic 2, JWT (access + refresh с ротацией), bcrypt, openpyxl, ReportLab |
| БД | PostgreSQL 17 (единственное постоянное хранилище), файлы — на диске сервера |
| Тесты | pytest (20), Vitest (9), Playwright E2E — полный офлайн-сценарий в Chromium |

## Быстрый старт

### Вариант A — Docker (рекомендуется для сервера)

Требуется установленный Docker с Compose.

```bash
cp .env.example .env    # при необходимости поменяйте JWT_SECRET и пароль БД
docker compose up --build
```

Откройте **http://localhost:8080**. Swagger: **http://localhost:8080/api/docs**.
При первом старте применяются миграции и создаются демо-данные (`SEED_DEMO=true`). Для промышленной установки
поставьте `SEED_DEMO=false`, задайте `JWT_SECRET`, `POSTGRES_PASSWORD`, `COOKIE_SECURE=true` и включите HTTPS (см. `docs/DEPLOYMENT.md`).

> Docker-конфигурация подготовлена, но **на машине разработки Docker не установлен, поэтому `docker compose up` не запускался**.
> Приложение проверено в варианте B (те же код, миграции и PostgreSQL 17).

### Вариант B — без Docker (как проверялось при разработке)

```bash
./scripts/setup.sh      # один раз: переносимые Node 24 и PostgreSQL 17 в .tools/, Python venv, npm-пакеты
./scripts/dev.sh        # PostgreSQL :5433 → миграции → seed → API :8000 → PWA-сборка :4173
```

- Приложение (PWA, Service Worker включён): **http://localhost:4173**
- Режим разработки с hot reload (без Service Worker): `./scripts/dev.sh --hot` → http://localhost:5173
- **С телефона в локальной сети по HTTPS:** `./scripts/dev.sh --https` → https://<IP-компьютера>:4443 — инструкция по установке
  сертификата на Android/iPhone: [docs/MOBILE_HTTPS.md](docs/MOBILE_HTTPS.md)
- API и Swagger: **http://localhost:8000/api/docs**

### Демо-видео

```bash
./scripts/demo-video.sh    # записывает 2 ролика (методист, сотрудник-смартфон) на тестовой БД → demo-videos/*.mp4
```

### Тесты

```bash
./scripts/test.sh          # pytest + tsc + vitest + сборка + E2E офлайн-сценарий в Chromium
./scripts/test.sh --fast   # без E2E
```

## Ключевой сценарий демонстрации

1. Войти как **methodist@dolce.local** → «Создать курс» → название «Техника безопасности на производстве», описание, обложка (drag & drop).
2. Добавить модуль и уроки → «Добавить элемент» → **Видео** (MP4/WebM/MOV, прогресс загрузки, авто-определение длительности и превью-кадр), **PDF**, текст/инструкция.
3. «Конструктор тестов» → новый тест, 5 вопросов (одиночный/множественный выбор, открытый ответ, последовательность) → «Опубликовать».
4. В уроке «Добавить элемент» → «Тест». «Опубликовать» курс → «Назначить сотрудникам».
5. Войти как **employee@dolce.local** (лучше со смартфона или в отдельном браузере) → курс в «Мои курсы» → **«Скачать для офлайн-доступа»**.
6. Включить авиарежим (или DevTools → Network → Offline) → обновить страницу: приложение открывается из кэша, баннер «Офлайн-режим».
7. Посмотреть видео (воспроизводится с устройства), открыть PDF, пройти тест → «Ответы сохранены на устройстве».
8. Вернуть сеть → синхронизация запускается автоматически (индикатор в шапке) → «Тест сдан!».
9. Методист → «Аналитика»: статус «Завершён», балл, «офлайн», время обучения; «Сертификаты и протоколы» → PDF.

Весь этот сценарий автоматически проверяется тестом `frontend/e2e/offline.spec.ts` (Playwright, Chromium, реальный Service Worker,
отключение сети через `context.setOffline`).

## Что реализовано

**Авторизация и роли.** Вход/выход, JWT access (15 мин, только в памяти) + refresh (httpOnly cookie, ротация, отзыв семейства
при повторном использовании), восстановление сессии после перезагрузки, bcrypt, ограничение попыток входа, смена пароля,
блокировка пользователей, проверка ролей и области подразделения на backend, защищённые маршруты на frontend.

**Кабинет методиста / администратора.** Дашборд (сотрудники, курсы, активные, назначения, % завершения, просрочки, средний балл,
часы обучения, графики, последняя активность, быстрые действия) и все 12 разделов меню: курсы, создание курса, библиотека,
конструктор тестов, сотрудники, подразделения, назначения, аналитика, компетенции 180/360, сертификаты и протоколы, настройки
(+ проверка открытых ответов, диалоговый тренажёр, журнал аудита).

**Конструктор курсов.** Все поля формы из ТЗ, модули → уроки → элементы 12 типов (текст, видео, PDF, Word, Excel, PowerPoint,
изображение, ссылка, тест, инструкция, доп. файл, тренажёр), изменение порядка, перенос урока в другой модуль, редактирование,
удаление, версия курса. Нельзя опубликовать пустой курс; курс с историей обучения не удаляется, а архивируется.

**Загрузка файлов.** Выбор/drag & drop, прогресс, отмена, белый список расширений + проверка сигнатуры содержимого (magic bytes),
лимиты (видео 1 ГБ, документы 100 МБ, настраиваются), случайные имена файлов, хранение вне web-root, выдача только после
проверки прав (Bearer или подписанная HMAC-ссылка с истечением), поддержка HTTP Range для перемотки видео.

**Кабинет сотрудника.** Главная (приветствие, подразделение, общий прогресс, незавершённые курсы, сроки, результаты, сертификаты),
мои курсы, каталог, библиотека, тесты, результаты, сертификаты, профиль, офлайн-доступ, оценки 360. Экран урока с модулями,
прогрессом, «Назад/Следующий урок», возобновлением видео с места остановки.

**Тесты.** 4 типа вопросов, баллы, объяснения, проходной балл, лимит времени (автозавершение), попытки, перемешивание, выборка
N вопросов, окно доступности, статус. Проверка — только на сервере; правильные ответы не передаются клиенту до завершения попытки;
ручная проверка открытых ответов. Ответы сохраняются построчно в `test_answers`.

**Офлайн и синхронизация** — см. раздел ниже.

**Аналитика и экспорт.** Обзор, динамика времени, статусы, подразделения; отчёты по сотрудникам, курсам и детальный; фильтры по
сотруднику, подразделению, курсу, периоду, статусу, результату, баллу; экспорт **XLSX** и **CSV** (с BOM для Excel); карточка
сотрудника с временем по курсам/урокам/видео и историей попыток.

**180/360.** Модель компетенций с индикаторами, шкала, назначение оценки (самооценка, руководитель, коллеги), заполнение
сотрудником, сводный профиль: таблица, средние, сравнение по типам оценки, радар-диаграмма.

**Документы.** PDF-сертификат (ФИО, курс, дата, балл, статус, уникальный номер) выдаётся автоматически при завершении курса;
PDF-протокол аттестации («Аттестован / Не аттестован», комиссия) — генерация на backend (ReportLab, шрифт DejaVu с кириллицей).

**Диалоговый тренажёр.** Редактор сценариев (персонажи, реплики, варианты, переходы, правильные/неправильные решения, баллы,
обратная связь), прохождение в формате чата, работает офлайн в составе скачанного курса; балл пересчитывается сервером
с проверкой корректности пути.

## Что работает офлайн

| Функция | Офлайн |
|---|---|
| Открытие приложения (оболочка, шрифты, pdf.js) | ✅ Service Worker precache |
| Вход для ранее авторизованного пользователя | ✅ локальная сессия до 14 дней (без пароля и токенов) |
| Скачанные курсы: структура, текст, инструкции | ✅ IndexedDB |
| Видео, PDF, изображения, Office-файлы скачанных курсов | ✅ Cache Storage (файлы целиком), видео/PDF смотрятся внутри приложения |
| Прохождение тестов и тренажёров | ✅ ответы сохраняются локально; **оценка — после синхронизации сервером** |
| Прогресс уроков, позиция видео, время обучения | ✅ очередь событий |
| Главная, мои курсы, библиотека, результаты, сертификаты (списки) | ✅ последний сохранённый снимок |
| Файлы библиотеки | ✅ если нажать «Сохранить офлайн» |
| Внешние ссылки, первый вход, создание контента, аналитика, PDF-сертификаты | ❌ требуется сеть |

**Синхронизация:** UUID у каждого события, идемпотентность на сервере (уникальный `sync_events.event_uuid`, UUID попытки как
первичный ключ), статусы pending / syncing / synced / failed, повторы с нарастающей задержкой, Web Locks против параллельной
отправки из нескольких вкладок. Триггеры: открытие приложения, событие `online`, возврат приложения на передний план, таймер,
кнопка «Синхронизировать сейчас». Background Sync намеренно не используется как единственный механизм (нет в Safari/iOS).
Пользователь видит статус сети, число ожидающих событий, время последней синхронизации и ошибки.

**Учёт времени:** время идёт только при видимой вкладке (Visibility API) и активности пользователя за последние 60 с либо при
воспроизведении видео; heartbeat каждые 30 с; считает только одна вкладка; сервер ограничивает событие 60 с; отдельно учитывается
время просмотра видео. Время офлайн-событий зависит от часов устройства — сервер не принимает «будущие» отметки, но не
выдаёт локальное время за абсолютно достоверное.

## Ограничения и известные проблемы

- **Docker не проверен** на этой машине (Docker не установлен) — конфигурация написана, но `docker compose up` не запускался.
- **PWA на смартфоне.** Для локальной сети настроен HTTPS с локальным CA (`./scripts/dev.sh --https`, `docs/MOBILE_HTTPS.md`):
  проверено в Chromium по LAN-адресу (защищённый контекст, Service Worker, открытие без сети). На реальном телефоне в авиарежиме
  не проверялось; Safari/iOS не тестировался.
- Встроенная браузерная панель Claude не регистрирует Service Worker (ограничение панели) — офлайн проверялся в Playwright.
- Word/Excel/PowerPoint не отображаются внутри приложения — открываются/скачиваются (в т.ч. офлайн) системным приложением.
- Офлайн-результат теста показывается только после синхронизации (ответы на устройство не передаются — это защищает аттестацию).
- Большие видео при скачивании собираются в память браузера перед записью в кэш; на слабых телефонах для роликов > 300–500 МБ
  возможны ошибки — приложение показывает ошибку и проверяет квоту заранее. Рекомендуется сжимать учебные видео (720p).
- Видео, записанные браузером (WebM через MediaRecorder), часто не содержат длительности в метаданных.
- Языки RU / ҚАЗ / EN: переведены оболочка, вход и весь кабинет сотрудника (переключатель в шапке, меню и профиле;
  выбор сохраняется на устройстве и в профиле). Кабинет методиста, сообщения сервера об ошибках и содержимое курсов — на русском.
  Казахский перевод выполнен без носителя языка — перед внедрением нужна вычитка.
- Ограничение попыток входа хранится в памяти процесса (для нескольких экземпляров backend — вынести в Redis).
- Нет восстановления пароля по email (по ТЗ — через администратора), нет SSO/LDAP, нет SCORM.
- Нет перетаскивания (drag & drop) для изменения порядка модулей/уроков — используются кнопки ↑/↓ (удобно на смартфоне).

## Резервное копирование

```bash
./scripts/backup.sh            # Docker: pg_dump (custom format) + архив storage → backups/<дата>/
./scripts/backup.sh --local    # локальный запуск (нужен pg_dump 17)
./scripts/restore.sh backups/20261120_120000
```

Рекомендуется ежедневный cron + хранение копий на отдельном носителе в периметре компании. Подробнее — `docs/DEPLOYMENT.md`.
