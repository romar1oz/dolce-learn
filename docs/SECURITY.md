# Безопасность и персональные данные

> Документ описывает реализованные технические меры. Он **не является заключением о соответствии** Закону РК
> «О персональных данных и их защите», требованиям к локализации данных или GMP/GxP-требованиям к компьютеризированным
> системам. Перед промышленным внедрением необходима проверка юристом и службой ИБ, а для использования в аттестации
> по GMP — валидация системы (CSV) по процедурам предприятия.

## Реализовано

| Мера | Где |
|---|---|
| Хеширование паролей bcrypt (cost 12) | `app/security/tokens.py` |
| JWT access 15 мин (только в памяти браузера), refresh 14 дн. в httpOnly SameSite=Strict cookie с путём `/api/auth`, ротация, отзыв семейства при повторном использовании, отзыв всех сессий при смене пароля/роли/блокировке (`token_version`) | `app/api/auth.py` |
| Ограничение перебора паролей (8 ошибок / 5 мин на пару email+IP) | `app/api/auth.py` |
| Проверка ролей на каждом endpoint; руководитель видит только своё подразделение; сотрудник — только свои данные | `app/core/deps.py`, роутеры |
| Только Super Admin назначает Super Admin; нельзя изменить собственную роль или заблокировать себя | `app/api/org.py` |
| SQL injection: только параметризованные запросы SQLAlchemy | везде |
| XSS: React экранирует вывод; учебный текст рендерится собственным безопасным парсером без HTML; CSP в nginx; `X-Content-Type-Options: nosniff` для файлов | `RichText.tsx`, `nginx.conf` |
| Загрузка файлов: белый список расширений, проверка сигнатуры содержимого, лимиты размера, случайные имена, файлы вне web-root, защита от path traversal | `app/services/storage.py` |
| Доступ к файлам — только после проверки прав на курс/библиотеку; ссылки для `<video>` подписаны HMAC и истекают | `app/services/access.py`, `app/api/materials.py` |
| CORS — только список источников из `CORS_ORIGINS` | `app/main.py` |
| Журнал аудита: входы (в т.ч. неудачные), выходы, изменения пользователей, курсов, тестов, назначений, загрузки, удаления, выдача сертификатов, ручная проверка | `audit_logs`, «Настройки → Журнал аудита» |
| Секреты — через переменные окружения (`.env` не попадает в git) | `.env.example` |
| Тест: правильные ответы не передаются клиенту до завершения попытки; офлайн-попытка оценивается сервером; на сервере проверяются лимит попыток, окно доступности, состав вопросов; путь в тренажёре проверяется | `app/services/grading.py`, `packages.py` |
| Офлайн: пароль и токены не хранятся на устройстве; локальная сессия ограничена 14 днями и сроком refresh-токена; роль из локальной сессии влияет только на интерфейс — сервер повторно проверяет права при синхронизации; события другого пользователя не отправляются | `stores/auth.ts`, `offline/sync.ts` |
| Время устройства: «будущие» отметки обрезаются до времени сервера; heartbeat ≤ 60 с; офлайн-события помечаются `source=offline` | `app/services/sync.py` |
| Только синтетические данные в seed | `app/seed.py` |

## Что проверить перед промышленным внедрением

1. Задать уникальные `JWT_SECRET` (`openssl rand -hex 32`) и `POSTGRES_PASSWORD`, `SEED_DEMO=false`, `COOKIE_SECURE=true`, `ENVIRONMENT=production`.
2. Включить HTTPS (TLS 1.2+), HSTS; ограничить доступ к серверу сетью предприятия/VPN.
3. Удалить или заблокировать демо-аккаунты, если seed запускался.
4. Политика паролей и регламент их выдачи; при необходимости — интеграция с AD/LDAP (не реализовано).
5. Шифрование дисков сервера и резервных копий; регламент хранения и уничтожения копий.
6. Согласия сотрудников на обработку ПДн, перечень обрабатываемых данных, сроки хранения, ответственные лица.
7. Размещение сервера и БД на территории РК (см. `DEPLOYMENT.md`) — архитектура не использует внешних облачных сервисов,
   CDN и AI-API: все шрифты, библиотеки и файлы обслуживаются с вашего сервера.
8. Мониторинг журнала аудита и логов nginx/uvicorn; ротация логов.
9. Валидация (IQ/OQ/PQ) при использовании результатов в GMP-аттестации; электронные подписи протоколов не реализованы —
   протокол печатается и подписывается комиссией.
10. Пентест / сканирование зависимостей (pip-audit, npm audit) перед запуском.
