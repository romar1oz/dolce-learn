# Развёртывание, PWA на смартфонах, резервное копирование

## 1. Локальный сервер предприятия (рекомендуемая схема)

```
Смартфоны / ПК сотрудников ──HTTPS──▶ nginx (frontend, :443) ──▶ FastAPI (backend) ──▶ PostgreSQL
                                              └── /data/storage (видео, документы)
```

Все компоненты разворачиваются на одном сервере (или ВМ) в серверной Dolce Pharm либо в дата-центре на территории
Республики Казахстан. Внешние сервисы не требуются: нет CDN, облачных хранилищ, внешних AI-API; шрифты и библиотеки
входят в сборку.

Требования: Linux x64, Docker + Compose, 2 vCPU, 4 ГБ RAM, диск под видео (оценка: 100 часов видео 720p ≈ 50–80 ГБ).

```bash
git clone … dolce-learn && cd dolce-learn
cp .env.example .env
# обязательно: JWT_SECRET, POSTGRES_PASSWORD, SEED_DEMO=false, COOKIE_SECURE=true, CORS_ORIGINS=https://learn.dolce.local
docker compose up -d --build
```

## 2. HTTPS — обязательно для PWA и офлайн-режима

Service Worker и установка PWA работают только по HTTPS (исключение — `http://localhost`).
Варианты:

**A. Корпоративный сертификат** — поставьте TLS-терминатор (nginx/Caddy/балансировщик) перед контейнером `frontend`
и проксируйте на порт 8080.

**B. Caddy с внутренним CA** (быстро для пилота в локальной сети):

```
# Caddyfile
learn.dolce.local {
    tls internal
    reverse_proxy 127.0.0.1:8080
}
```

Корневой сертификат Caddy (`caddy trust` / файл `root.crt`) нужно установить на смартфоны:
- **Android:** Настройки → Безопасность → Шифрование и учётные данные → Установить сертификат → Сертификат ЦС.
- **iOS:** открыть файл сертификата → Настройки → Профиль загружен → Установить; затем Основные → Об этом устройстве →
  Доверие сертификатам → включить для сертификата.

DNS-имя `learn.dolce.local` должно указывать на сервер (корпоративный DNS или запись в роутере).

## 3. Установка PWA на смартфон

1. Откройте адрес Dolce Learn (HTTPS) и войдите.
2. **Android (Chrome):** меню ⋮ → «Установить приложение» / «Добавить на главный экран».
3. **iPhone (Safari):** кнопка «Поделиться» → «На экран «Домой»».
4. Запустите Dolce Learn с иконки, откройте курс → «Скачать для офлайн-доступа» → дождитесь «Доступен офлайн».
5. Раздел «Офлайн-доступ» показывает скачанные курсы и занятое место; кнопка «Запросить» просит браузер не очищать данные.

Особенности iOS: Safari может очистить данные сайта, который не открывали несколько недель, — PWA, установленное на экран
«Домой», защищено лучше. Перед длительной работой без сети откройте приложение онлайн для синхронизации.

## 4. Резервное копирование

```bash
./scripts/backup.sh                       # → backups/YYYYMMDD_HHMMSS/{dolce_learn.dump, storage.tar.gz}
./scripts/restore.sh backups/20261120_120000
```

Пример cron (ежедневно в 02:30, хранить 30 дней):

```
30 2 * * * cd /opt/dolce-learn && ./scripts/backup.sh && find backups -maxdepth 1 -mtime +30 -exec rm -rf {} +
```

Копируйте `backups/` на отдельный носитель / сервер в периметре предприятия. Периодически проверяйте восстановление на
тестовом стенде. База без файлов `storage` неполна — сохраняйте оба архива.

## 5. Обновление

```bash
git pull && docker compose up -d --build     # миграции Alembic применяются автоматически при старте backend
```

После обновления пользователи увидят в приложении «Доступна новая версия» (Service Worker).

## 6. Интеграция с 1С и Битрикс24

REST API описан в OpenAPI: `/api/openapi.json`, интерактивно — `/api/docs`. Для интеграции создайте служебного пользователя
с ролью «Методист» и используйте Bearer-токен (`POST /api/auth/login`).

| Задача | Endpoint |
|---|---|
| Выгрузка сотрудников из 1С (создание/обновление) | `POST /api/users`, `PATCH /api/users/{id}` (табельный номер — `employee_number`) |
| Подразделения | `GET/POST/PATCH /api/departments` |
| Назначение обязательного обучения | `POST /api/assignments` (`user_ids` или `department_ids`, `due_date`) |
| Результаты обучения в 1С/Битрикс24 | `GET /api/analytics/report` (JSON) или `GET /api/reports/export?format=csv|xlsx` |
| Время обучения за период | `GET /api/reports/time?date_from=&date_to=` |
| Сертификаты, проверка подлинности | `GET /api/certificates`, `GET /api/certificates/verify/{number}` |

Рекомендуется вынести долгоживущие API-ключи для интеграций в отдельную сущность (не реализовано) и настроить вебхуки
при завершении курса (не реализовано).
